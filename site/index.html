How a call works

Voxie runs the call. Your app decides what to say.

  1. 01 · Caller

    Browser or phone

    WebRTC (WHIP) from a browser, Twilio Media Streams for phone calls, or any SIP trunk through sip-server.

  2. 02 · Voxie server :8080

    Hears and takes turns

    Speech detection, turn-taking, barge-in, echo guard, and speech-to-text that adapts to the caller.

  3. 03 · Your agent

    Decides what to say

    Voxie posts each turn to one HTTP endpoint of yours, with its language. You reply with text.

  4. 04 · Voice router :8300

    Speaks it

    Sentence by sentence: Kokoro on the GPU in ~130ms a sentence, Sarvam for Indian languages.

Integrate

Three steps to a voice agent.

Voxie is open source. The images are published; the rest is your own app.

1

Run Voxie

Add your provider keys and start the server and the voice router. You need keys for Deepgram, Groq and Sarvam (AssemblyAI is optional), and an NVIDIA GPU for the voice router.

git clone https://github.com/SomehowLiving/Voxie.git && cd Voxie
cp .env.example .env                        # DEEPGRAM_API_KEY, GROQ_API_KEY, SARVAM_API_KEY
docker compose -f compose.release.yaml up   # server :8080 · voice router :8300 · test page :8400
2

Point it at your app

One config for every caller. Set your agent's URL and a shared key; Voxie sends it as a bearer token on every request.

[agent]
url = "https://your-app.example.com/voice/agent"
api_key = "…"        # or STREAMCORE_AGENT_API_KEY

[stt]
provider = "adaptive"   # a listener per call
3

Answer four requests

Voxie posts each event of the call to your endpoint and speaks what you send back.

typeWhenReply
listenBefore speech-to-text starts{ language?, region? }
greetingThe caller stayed silent{ text }
chatThe caller finished a turn{ text, end_call? }
oneshotBackground work{ text: "" }
 
// A whole agent: Node 20+, no dependencies.
import { createServer } from "node:http";

createServer(async (req, res) => {
  let body = "";
  for await (const chunk of req) body += chunk;
  const turn = JSON.parse(body);   // { session_id, resource_id, type, text, language }

  let reply = { text: "" };
  if (turn.type === "listen") reply = {};   // or what you know: { language: "hi", region: "IN" }
  if (turn.type === "greeting") reply = { text: "[lang:en] Hi, this is Voxie. How can I help?" };
  if (turn.type === "chat") reply = { text: await think(turn.text, turn.language) };

  res.writeHead(200, { "Content-Type": "application/json" });
  res.end(JSON.stringify(reply));
}).listen(9101);

async function think(text, language = "en") {   // your app goes here
  return `[lang:${language}] You said: ${text}`;
}

Published images

Pull it, don't build it.

Both halves of Voxie are on GitHub's container registry, built for linux/amd64 with the Apache 2.0 licence and StreamCore's notice inside. Pin a version in production.

  • voxieThe server: hearing, turn-taking, barge-in · about 740 MB
    ghcr.io/somehowliving/voxie:56d3a3b
  • voxie-voice-routerThe voice: Kokoro, Piper and Sarvam, needs an NVIDIA GPU · about 4.8 GB
    ghcr.io/somehowliving/voxie-voice-router:56d3a3b
docker pull ghcr.io/somehowliving/voxie:56d3a3b
docker pull ghcr.io/somehowliving/voxie-voice-router:56d3a3b
VOXIE_TAG=56d3a3b docker compose -f compose.release.yaml up

Reply in the caller's language

Start each sentence with [lang:xx], for example [lang:ta]. Hindi and Marathi share a script, so text alone can't tell them apart. Answer only in languages the router's GET /health lists right now.

Phone calls through Twilio

Set TWILIO_AUTH_TOKEN, then connect the call's audio to Voxie. No SIP trunk and no public IP: a public URL is enough.

<Response><Connect><Stream url="wss://<voxie-host>/twilio/media">
  <Parameter name="resource_id" value="+919812345678"/>
</Stream></Connect></Response>

Stream your replies

Reply as text/event-stream and Voxie voices the first sentence while the rest is on its way. Send {"end_call": true} to hang up once the goodbye has played.

Honest limits

What we haven't proven yet.

  • Tested mostly with synthetic voices, clean and at phone quality, plus a real phone call through Twilio to an Indian mobile. A pilot with real callers is next.
  • A turn that may have been misheard waits 0.4–1s for its language to be identified, usually only the caller's first real turn.
  • The voice router needs an NVIDIA GPU, and free API tiers run out quickly under multilingual load: plan on paid tiers for Groq and Sarvam.
